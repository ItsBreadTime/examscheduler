# สถานะการตรวจสอบ (Verification) — คู่มือการใช้งาน Exam Scheduler

## สรุป

คู่มือการใช้งานระบบจัดตารางสอบ Exam Scheduler จัดทำเป็นเอกสาร Thai LuaLaTeX
จำนวน **48 หน้า** ประกอบด้วยบทที่ 1–9 และภาคผนวก A–D พร้อมภาพประกอบที่ถ่ายจาก
แอปพลิเคชันจริงโดยใช้ข้อมูลสังเคราะห์

## การแก้ไขรอบ QC (6 กันยายน 2026, รอบที่ 2)

- ปก: ลบย่อหน้าข้อความสงวนสิทธิ์ออกจากหน้าปก จัดตรา FITM และ KMUTNB
  ไว้ในแถวเดียวกัน (ความสูงเท่ากัน 2.2cm) พร้อมชื่อคณะและมหาวิทยาลัย
- สารบัญ: จุดนำสายตา (dot leaders) สม่ำเสมอทั้งสารบัญ สารบัญรูป และ
  สารบัญตาราง (`tocloft` + `cftdotsep` 2.5) และแยกสารบัญรูป/ตาราง
  ขึ้นหน้าใหม่ไม่ให้ติดท้ายสารบัญ
- ตาราง: ระยะห่างแถวทั่วทั้งเล่มด้วย `\arraystretch` 1.45 (ใช้กับรายงาน
  ทางเทคนิคด้วยผ่าน `docs/report.tex`)
- กรอบข้อสังเกต: บล็อก `expected`/`caution` มีแถบสีหนา 3pt ที่ขอบซ้าย
  (เขียว/แดง) เนื้อหาชิดซ้ายแบบ `RaggedRight`
- การจัดข้อความไทย: เอกสารทั้งฉบับใช้ `RaggedRight` แทนการจัดเต็มแนว
  แก้ช่องโหว่ระหว่างกลุ่มคำภาษาไทยที่เกิดจากการยืดบรรทัด (kerning QC)

## การแก้ไขรอบ QC (6 กันยายน 2026, รอบที่ 3)

- ตัดบทนำ/โน้ตสำหรับผู้พัฒนาออกจากเนื้อหาหลัก: ย่อหน้าที่อยู่เซิร์ฟเวอร์ (บทที่ 1 และ 8)
  ข้อความเรื่องหน้าจัดห้องที่ถูกซ่อน (บทที่ 5) และหมายเหตุเรื่องตัวแก้ไขตารางในตัว (บทที่ 6)
- ลดจำนวนบล็อก "ผลที่ควรเห็น" เหลือเฉพาะจุดที่ผลลัพธ์มีผลต่อการตัดสินใจ ลด "ข้อควรระวัง"
  เหลือเฉพาะจุดที่เสี่ยงข้อมูลหาย/ความปลอดภัย/พฤติกรรมที่คาดไม่ถึง และย่อคำอธิบายภาพ
- แก้ความขัดแย้งของเนื้อหา: คอลัมน์เสริมที่ระบบอ่านจริง (ชี้ไปภาคผนวก A)
  ความหมายของช่วงเวลา 09:00–12:00/13:00–16:00 (ใช้กับการจัดอัตโนมัติเท่านั้น)
  วิชาที่ยังไม่ได้จัด (สอนขั้นตอนกำหนดเวลาครบถ้วน) การจัดตารางใหม่ (ระบุชัดว่ายกเลิกการล็อกเวลาทุกครั้ง)
  และข้อจำกัดของ `project.zip` (นำกลับเข้าระบบไม่ได้) ให้สอดคล้องทุกบท
- รวมหัวข้อซ้ำ (9.2+9.5), ปรับบทที่ 7 ให้ตารางเปรียบเทียบวิธีเก็บงานเป็นแกนของบท
  ย้ายรายละเอียด JSON ของ `project.zip` ไปภาคผนวก B, ใช้คำว่า "ฉบับ" และ "คลาวด์" ให้ตรงกับ UI ทั้งเล่ม
- ตารางเปรียบเทียบ/ตารางสิทธิ์ใช้เครื่องหมาย ✓/– (ฟอนต์ Zapf Dingbats เพราะ Sarabun ไม่มี U+2713)
- ภาพหน้าจอ: ครอปรูปที่เป็น dialog และรูปที่ต้องการชี้จุดเฉพาะไว้ที่ `screenshots/crops/`
  (ตรวจสอบด้วย vision QC ต่อรูป) ตัวอย่างเวลาใน CSV ถูกยืนยันกับซอร์สโค้ด (`9-12`)
- ภาคผนวก D ออกแบบใหม่เป็น 6 กล่อง 3x2, รูปทั้งหมดวางด้วยตำแหน่ง [H] ให้อยู่ติดกับขั้นตอนที่สอน
  ปกตัดข้อความ "ฉบับสาธิต" ออก และลำดับหน้าเรียงต่อเนื่องขึ้น (61 เหลือ 48 หน้า)

## การแก้ไขรอบ QC (6 กันยายน 2026, รอบที่ 5, final production pass)

- ความสอดคล้องภายในสามจุดตามรายงาน QC:
  - บทที่ 2 และภาคผนวก A อธิบายรูปแบบไฟล์เงื่อนไขให้ตรงกับไฟล์จริง
    คือตารางที่แถวแรกเป็นหัวคอลัมน์ชื่อเงื่อนไข และมีรหัสวิชาในช่องใต้หัวคอลัมน์
    กลุ่มสอบตรงกันใส่รหัสต่อกันไปทางขวาได้หลายช่อง (ยืนยันกับ parser
    `src/lib/rules.ts` และตัวอย่าง `examples/*/rules.csv`) พร้อมเพิ่มคำอธิบาย
    วิธีนับแถว/คอลัมน์ (นับหัวตารางเป็นแถวที่ 1 เช่นเดียวกับโปรแกรมตารางคำนวณ)
    และชื่อชีต `Sheet1` ของไฟล์ CSV ในบทที่ 6 ที่อ้างหลักฐาน
    `rules.csv · Sheet1 · แถว 3 · คอลัมน์ 3` (ยืนยันด้วย `npm run schedule -- inspectImport`)
  - รูป 6.3 (F21) ย้ายมาอยู่ก่อนขั้นตอนแก้ไขและเปลี่ยนคำอธิบายเป็น
    "ตัวอย่างก่อนแก้ไข" พร้อมผลที่ควรเห็นหลังแก้ (10/11 เป็น 11/11)
  - ตัวอย่างตาราง CSV ในบทที่ 7 แสดงครบทั้งแปดคอลัมน์ตามรายการที่เนื้อหาระบุ
    (วันที่ เวลา รหัสวิชา ชื่อวิชา ตอนเรียน กลุ่มนักศึกษา ที่มา สถานะ)
    โดยใช้ค่าจริงสองแถวแรกจากไฟล์ส่งออก
- ภาพหน้าจอ: ถ่าย F20 และ F22 ใหม่จากแอปปัจจุบัน (Vite dev server)
  เพราะภาพเดิมแสดงป้ายชื่อข้อค้นพบรุ่นเก่า ภาพใหม่แสดงสถานะขยายรายละเอียด
  พร้อมบรรทัดหลักฐานตำแหน่งไฟล์ต้นทาง ตรวจสอบข้อความทุกบรรทัดด้วย vision
  และเทียบกับซอร์สโค้ด `src/ui/format.ts` และผล `inspectImport` ของ CLI
- ครอปรูป: F24a เหลือเฉพาะส่วนต้นของไฟล์ (หัวตารางและเจ็ดแถวแรก) ให้อ่านได้จริง
  F24b ครอปใหม่จากภาพ raw ให้เห็นการ์ดปฏิทินครบทุกขอบ (ตัดรอยตัดอักษร
  และพื้นที่ว่างด้านล่างออก) F27b/F28b เปลี่ยนเป็นแถบบนของหน้าผู้รับลิงก์
  ที่แสดงข้อความสิทธิ์ต่างกัน (ตารางสอบที่แชร์/สิทธิ์แก้ไขที่แชร์)
- การจัดหน้า: เพิ่ม `\needspace` กันหัวข้อกำพร้าท้ายหน้า (4.4, 5.3, 6.3, 8.7, A.3)
  ย่อตารางอภิธานศัพท์ (`\small` + arraystretch 1.25) จนไม่มีหน้าที่เหลือเพียงสองแถว
  ขยายคอลัมน์ "ไปที่" ของตารางเส้นทางใช้งานฉบับย่อ และปรับถ้อยคำหัวข้อรองบนปก
- เอกสารลดจาก 47 เหลือ 45 หน้า ยังคงผ่านประตูคุณภาพของ build ทุกข้อ
  (overfull 0, missing glyph 0, undefined reference 0)

## สถานะของขั้นตอน (Scenario)

รายละเอียดสถานะของแต่ละขั้นตอน (U01–U09, E01–E12, R01–R03, D01–D03, C01–C05)
อยู่ในไฟล์ `evidence/procedures.json` โดยแยกเป็น:
- **source** — ยืนยันจากซอร์สโค้ด
- **live** — ยืนยันจากการทดสอบจริงในเบราว์เซอร์

## ข้อจำกัดที่ทราบ

1. **การดาวน์โหลด ZIP ผ่านเบราว์เซอร์ของ OpenChrome** ไม่บันทึกไฟล์ลงดิสก์
   จึงใช้แกนส่งออกเดียวกันผ่าน CLI เพื่อตรวจสอบเนื้อหาของไฟล์เก็บถาวร
   (ยืนยันว่าไฟล์ `project.zip` มี 13 ไฟล์ ไม่รวมโฟลเดอร์ `sources/`)
2. **การหมดอายุของลิงก์แชร์** ยังไม่ได้ทดสอบแบบรอครบ 1 วันจริง
   แต่การเพิกถอนลิงก์แล้วเปิดใหม่ถูกยืนยันแล้ว (แสดง HTTP 401)
3. **การเปลี่ยนชุดข้อมูลแล้วนำเข้าใหม่** ยืนยันผลการนำเข้าแล้ว
   ส่วนการตัดการเชื่อมต่อคลาวด์/รายการแชร์เมื่อนำเข้าใหม่ยืนยันบางส่วน

## Word wrapping regression checks (6 September 2026)

- The build-only Thai segmentation pass covers the main manuscript, shared style,
  and all 13 chapter/appendix sources. Original manuscript wording is preserved.
- Dictionary boundaries keep `อัตโนมัติ` and `ปรากฏ` intact; Babel's
  character-level Southeast Asian fallback and automatic hyphenation are disabled.
- Code wrapping is limited to punctuation, rather than arbitrary letters/digits.
- `test-thai-typesetting.py` runs four regression checks before every build.
- The build rejects overfull boxes, missing glyphs, and undefined references before
  publishing the output PDF.

## Justification correction (6 September 2026)

- Restored full justification in body paragraphs and explanatory callouts.
- Dictionary-approved Thai word boundaries now carry zero-width stretchable
  spacing, distributing justification across words instead of expanding only
  the manuscript's explicit spaces. Thai words remain unbroken.
- Table columns retain their explicit alignment. Bookmark text excludes the
  typesetting-only boundary command.
