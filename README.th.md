# ระบบจัดตารางสอบ Exam Scheduler

[English](README.md)

ระบบจัดตารางสอบกลางภาคและปลายภาคจากไฟล์รายวิชาของระบบทะเบียน รองรับรูปแบบไฟล์ส่งออกของคณะเทคโนโลยีอุตสาหกรรม มหาวิทยาลัยเทคโนโลยีพระนครเหนือ (มจพ.) มาตั้งแต่ต้น หลักการของระบบคือความถูกต้องมาก่อนความครบถ้วน: ตารางที่ได้ต้องไล่ย้อนกลับไปถึงที่มาของข้อมูลได้ทุกชิ้น และต้องไม่ทำให้กลุ่มผู้เรียนเกิดข้อขัดแย้งขึ้นมาใหม่เด็ดขาด

ระบบแบ่งเป็นสามส่วนที่ทำงานร่วมกัน:

- **ไลบรารีหลักภาษา TypeScript** ทำหน้าที่นำเข้าไฟล์ ตรวจสอบความสอดคล้องของข้อมูล จัดตารางด้วยวันและเวลาที่เจาะจง และตรวจสอบผลลัพธ์แบบแยกจากตัวจัดตาราง โดยไม่พึ่งพา DOM, ที่เก็บข้อมูล หรือเครือข่ายแต่อย่างใด
- **เว็บแอปพลิเคชัน Svelte** ครอบคลุมขั้นตอนการใช้งานทั้งหมด ทุกอย่างประมวลผลในเครื่องของผู้ใช้ผ่าน Web Worker จึงไม่ต้องส่งไฟล์ไปที่ไหน อินเทอร์เฟซเริ่มต้นเป็นภาษาไทยและสลับเป็นอังกฤษได้ทันที
- **Cloudflare Worker** เพิ่มบริการบันทึกและแชร์งานผ่านคลาวด์แบบไม่บังคับ ส่วนการจัดตารางยังคงทำงานในเครื่องของผู้ใช้เสมอ

ระบบเวอร์ชันปัจจุบันเปิดใช้งานจริงอยู่ที่ <https://schedule.breadtm.xyz>

## ความสามารถหลัก

- อ่านไฟล์รายวิชาได้หลายรูปแบบ ทั้ง XLSX, XLS, XLSM, XLSB, CSV, TSV, ODS และ FODS รับวันที่คริสต์ศักราชและพุทธศักราช (เช่น 17/08/69)
- แยกบทบาทของไฟล์ชัดเจน ระหว่างให้ระบบจัดอัตโนมัติ กับไฟล์ที่จัดตารางไว้แล้วซึ่งอ่านเข้ามาเป็นข้อมูลบริบทโดยไม่แก้ไข
- ตั้งช่วงวันสอบกลางภาคและปลายภาค เวลาสอบในแต่ละวัน วันหยุดสุดสัปดาห์ และวันหยุดของสถาบันได้เองทั้งหมด
- ป้องกันกลุ่มผู้เรียนต้องสอบสองวิชาพร้อมกันโดยเด็ดขาด วิชาที่เงื่อนไขกำหนดให้สอบตรงกันจะถูกรวมเป็นหน่วยเดียวกันตอนจัดตาราง
- จัดห้องสอบและผู้คุมสอบต่อจากตารางเวลา พร้อมตรวจสอบความถูกต้องของการจัดทรัพยากรแบบแยกจากตัวจัดตาราง
- แก้ไขวันเวลาสอบของวิชาที่จัดอัตโนมัติได้ ทุกครั้งที่แก้จะถูกตรวจข้อขัดแย้งก่อนบันทึกเสมอ ส่วนวันสอบที่นำเข้าจากไฟล์ต้นทางเป็นแบบอ่านอย่างเดียว
- รายงานทุกข้อค้นพบชี้ไปถึงแหล่งที่มาในไฟล์ต้นทาง ไม่มีการแก้ไข ละเว้น หรือปกปิดข้อมูลโดยไม่แจ้งให้ทราบ
- บันทึกงานขึ้นคลาวด์และส่งต่อด้วยลิงก์ที่คุมสิทธิ์ได้ ตั้งวันหมดอายุได้ และเพิกถอนได้ทุกเมื่อ
- ทำงานแบบ deterministic ข้อมูลและการตั้งค่าชุดเดิมได้ผลลัพธ์ชุดเดิมทุกครั้ง พร้อมชุดทดสอบถดถอยครอบคลุมทั้งระบบ

## เริ่มต้นใช้งาน

ต้องมี Node.js เวอร์ชัน 22.18 ขึ้นไป

```sh
npm ci
npm run check
npm test
npm run build

# ตรวจปัญหาของไฟล์ต้นทางและช่วงวันสอบก่อนเริ่มจัดตาราง
npm run schedule -- tests/fixtures/manifest.json --inspect

# สร้างผลลัพธ์ตัวอย่าง พร้อมรายการปัญหาและวิชาที่ยังจัดไม่ได้
npm run schedule -- tests/fixtures/manifest.json --out output/sample-result.json

# เรียกผ่าน CLI ที่คอมไพล์แล้วก็ได้เช่นกัน
node dist/cli.js tests/fixtures/manifest.json --out output/sample-result.json

# เปิดเว็บแอปพลิเคชัน (ภาษาไทยเป็นหลัก สลับอังกฤษได้)
npm run dev
```

CLI จบการทำงานด้วยรหัสสามแบบ: `0` คือข้อมูลถูกต้อง (อาจมีคำเตือน), `2` คือไฟล์ต้นทางมีปัญหาหรือตารางยังไม่ถูกต้องหรือไม่สมบูรณ์ และ `1` คือความล้มเหลวของโปรแกรมหรือไฟล์ ผลลัพธ์จะยังถูกบันทึกแม้การตรวจสอบไม่ผ่าน ชุดไฟล์ตัวอย่างของมหาวิทยาลัยที่ให้มาตั้งใจให้จบด้วยรหัส `2`

ช่วงวันที่สิงหาคมและตุลาคม 2026 ใน manifest ตัวอย่างเป็นค่าสาธิต ไม่ใช่ปฏิทินสอบที่มีการอนุมัติแล้ว ให้คัดลอกไปแก้ช่วงวันและวันหยุดให้ตรงกับภาคการศึกษาจริงก่อนนำไปใช้

## การกำหนดค่า

การตั้งค่าทั้งหมดอยู่ใน manifest รูปแบบ JSON ที่ระบุไฟล์รายวิชาพร้อมบทบาทของแต่ละไฟล์ ไฟล์เงื่อนไขการสอบ ไฟล์ห้องสอบ และไฟล์ผู้คุมสอบ รวมถึงช่วงวันสอบของกลางภาคและปลายภาค ช่วงเวลาสอบต่อวัน รายการวันหยุด นโยบายการเลี่ยงวันหยุดสุดสัปดาห์และวันหยุดสถาบัน และงบประมาณการค้นหา (`searchBudget`) ที่กำหนดเวลาการทำงานให้จบได้แน่นอน

วิชาที่ให้ระบบจัดต้องสอบทั้งกลางภาคและปลายภาค เว้นแต่เงื่อนไขการสอบจะยกเว้นไว้ ส่วนกลุ่มผู้เรียนที่ขาดหายจะไม่ถูกเดาแทน แต่จะรายงานให้กลับไปแก้ที่ไฟล์ต้นทางเสมอ

รายละเอียดการตั้งค่าครบทุกช่อง รวมถึงรูปแบบไฟล์ที่รองรับและพฤติกรรมของตัวจัดตาราง อ่านต่อได้ที่ [README.md](README.md) ฉบับภาษาอังกฤษ

## เว็บแอปพลิเคชัน

`npm run dev` เปิดเว็บแอปพลิเคชันที่ใช้ไลบรารีเดียวกับ CLI วิธีใช้คือเลือกไฟล์รายวิชาพร้อมบทบาท ตั้งปฏิทินการสอบ นำเข้า ทบทวนข้อค้นพบจากไฟล์ต้นทาง แล้วจึงสร้างตาราง มุมมองครอบคลุมทั้งภาพรวม รายวิชา ปฏิทิน กลุ่มผู้เรียน ข้อควรตรวจสอบ ห้องสอบ ผู้คุมสอบ บันทึกและแชร์ ตรวจสอบ และความช่วยเหลือ สลับดูผลแยกกลางภาคและปลายภาคได้

- การนำเข้า การจัดตาราง และการตรวจสอบทำงานใน Web Worker หน้าจอจึงตอบสนองตลอด ยกเลิกระหว่างทำได้ และผลลัพธ์จากรอบที่ยกเลิกจะไม่ถูกนำไปใช้
- ปุ่มใช้ไฟล์ตัวอย่างโหลดชุดข้อมูลตัวอย่างมาให้ทดลองได้ทันทีโดยไม่ต้องแตะ CLI
- เซสชันล่าสุดถูกเก็บไว้ในเบราว์เซอร์ ปิดหน้าไปแล้วกลับมาทำต่อได้ทันที

## บันทึกและแชร์ผ่านคลาวด์

การจัดตารางทำงานในเครื่องของผู้ใช้เสมอ คลาวด์ทำหน้าที่เก็บและส่งต่อผลลัพธ์เท่านั้น:

- ทุกครั้งที่บันทึกจะสร้างรุ่นผลลัพธ์ใหม่แบบไม่มีการเขียนทับของเดิม ถ้ารุ่นต้นทางถูกแก้ไขไปก่อนหน้า ระบบจะแจ้งให้เปรียบเทียบและตัดสินใจเองแทนการทับกันโดยไม่แจ้ง
- ลิงก์โปรเจกต์ของเจ้าของเก็บข้อมูลลับไว้ในเบราว์เซอร์ของเจ้าของคนเดียว นำลิงก์ไปเปิดบนเครื่องอื่นก็ได้ทั้งโปรเจกต์รวมถึงไฟล์ต้นทาง
- ลิงก์แชร์แยกตามสิทธิ์ ตั้งแต่ดูตารางอย่างเดียว เพิ่มข้อมูลตรวจสอบ ไปจนถึงแก้ไข เลือกตามได้ทั้งรุ่นล่าสุดหรือรุ่นที่กำหนด ตั้งวันหมดอายุได้ และเพิกถอนได้ทุกเมื่อ

ผู้ที่ต้องการติดตั้งเอง หลังจาก `wrangler login` แล้วเตรียมทุกอย่างด้วยคำสั่งเดียว (รันซ้ำได้):

```sh
npm run cloud:provision   # สร้าง bucket ฐานข้อมูล และตาราง พร้อม deploy ในครั้งเดียว
npm run cloud:deploy      # build เว็บแอปแล้ว deploy ทั้งแอปและ API พร้อมกัน
npm run cloud:migrate      # อัปเดตโครงสร้างฐานข้อมูลเมื่อมีการเปลี่ยนแปลง
```

worker ที่ปล่อยไปแล้วให้บริการทั้งเว็บแอปและ API บน origin เดียวกัน จึงไม่ต้องตั้งค่า URL เพิ่มเติม และการส่งออกแบบ ZIP ใช้ได้ตามปกติแม้ไม่มีคลาวด์

## เอกสารประกอบ

- [คู่มือการใช้งาน](docs/usage-report.pdf) คู่มือปฏิบัติทีละขั้น ตั้งแต่การเตรียมข้อมูล การนำเข้า การอ่านผลลัพธ์ การแก้ไขวันสอบ ไปจนถึงวิธีแก้ปัญหาที่พบบ่อย
- [รายงานทางเทคนิค](docs/report.pdf) เหตุผลการออกแบบ พฤติกรรมของตัวจัดตาราง ผลการวัดประสิทธิภาพ และการตรวจสอบระบบที่ใช้งานจริง

ทั้งสองฉบับเป็นภาษาไทยทั้งเล่ม ส่วนรายละเอียดการกำหนดค่าและพฤติกรรมของระบบในระดับลึก อยู่ใน [README.md](README.md) ฉบับภาษาอังกฤษ

## งานที่ยังเหลือ

การดึงปฏิทินวันหยุดโดยอัตโนมัติยังไม่ได้ทำ นอกเหนือจากนี้ ตั้งแต่การนำเข้าไฟล์ การจัดตารางพร้อมการล็อกเวลาด้วยตนเอง การจัดห้องสอบและผู้คุมสอบ ไปจนถึงการบันทึกคลาวด์ การแชร์ และการส่งออกเพื่อการจัดเก็บ ทำครบและมีชุดทดสอบรองรับแล้วทั้งหมด
